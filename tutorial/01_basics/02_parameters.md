# 02 — Параметри: temperature, max_tokens, top_p, stop_sequences

## Як модель генерує текст (спрощено)

LLM — це по суті функція: **отримує всі попередні токени → повертає ймовірність для кожного наступного токена**.

Наприклад після фрази "The capital of France is" модель видає щось таке:
```
"Paris"    → 94%
"Lyon"     → 2%
"a"        → 1%
...інші    → 3%
```

Параметри семплінгу контролюють **як обирається наступний токен з цього розподілу**.

---

## temperature

Масштабує логіти (сирі числа) перед softmax-ом.

- `temperature=0` → завжди беремо найімовірніший токен (argmax). **Детерміновано** — однаковий запит дасть однакову відповідь.
- `temperature=1` → стандартний розподіл, модель семплює з нього. **Варіативно.**
- `temperature>1` → розподіл "розмивається", модель стає більш хаотичною (Anthropic не рекомендує).

**Коли що використовувати:**
| Задача | Temperature |
|---|---|
| Витягнути факт, SQL, JSON | 0 |
| Написати текст, пояснення | 0.3–0.7 |
| Брейнсторм, творчість | 0.8–1 |

---

## max_tokens

Жорсткий ліміт на кількість **output** токенів. SDK вимагає завжди вказувати його явно.

Якщо модель досягає ліміту — відповідь обрізається посередині речення, а `stop_reason` стає `"max_tokens"`.

**Підводний камінь:** `max_tokens` — це ліміт на output, але вся генерація (input + output) не може перевищувати **context window** моделі (200k для Claude). Тобто якщо ти відправив 199k токенів, то для відповіді залишився лише 1k.

---

## stop_sequences

Рядки, при появі яких генерація зупиняється. Самі рядки **не включаються** у відповідь.

```ts
stop_sequences: ["###", "END"]
```

Корисно для:
- Парсингу структурованих виводів (зупинись після `</answer>`)
- Симуляції персонажів (зупинись якщо модель починає нову "роль")

---

## top_p (nucleus sampling)

Замість фіксованої кількості токенів — беремо найімовірніші токени, поки їх сумарна ймовірність не досягне `p`.

- `top_p=0.1` → розглядаємо лише токени що разом дають 10% ймовірності (дуже консервативно)
- `top_p=1.0` → розглядаємо всі токени (дефолт)

**Anthropic рекомендує міняти або `temperature`, або `top_p` — не обидва одночасно.** Вони обидва контролюють "ширину" семплінгу і разом дають непередбачуваний ефект.

---

## Підводні камені

**1. temperature=0 не гарантує 100% детермінізм.**
На практиці можуть бути мінімальні варіації через паралельні обчислення на GPU (floating point недетермінізм). Але для практичних задач — вважай детерміновано.

**2. Низький max_tokens + довга відповідь = мовчазна обрізка.**
Модель не поверне помилку — просто обріже. Перевіряй `stop_reason === "max_tokens"` якщо потрібна повна відповідь.

**3. stop_sequences чутливі до регістру.**
`"END"` і `"end"` — різні рядки.
