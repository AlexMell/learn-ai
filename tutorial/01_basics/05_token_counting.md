# 05 — Токени

## Що таке токен

Токен — одиниця тексту якою оперує модель. Це **не символ і не слово** — щось між ними.

Приблизно:
- 1 токен ≈ 4 символи англійського тексту
- 1 токен ≈ ¾ слова
- 100 токенів ≈ 75 слів

Токенізація відбувається через алгоритм **BPE (Byte Pair Encoding)**: часті комбінації символів стають одним токеном. "programming" → 1 токен, але "програмування" → 3–4 токени (нелатинські мови менш ефективні).

Можна подивитись як токенізується текст: [platform.openai.com/tokenizer](https://platform.openai.com/tokenizer) (алгоритм схожий).

---

## Чому це важливо

1. **Ціна** — ти платиш за токени, не за символи.
2. **Context window** — максимум ~200k токенів разом (input + output).
3. **Швидкість** — більше токенів = повільніша генерація.

---

## countTokens() — підрахунок до запиту

```ts
const count = await client.messages.countTokens({
  model: "claude-sonnet-4-6",
  system: "...",
  messages: [...]
});
console.log(count.input_tokens); // скільки токенів в твоєму промпті
```

Це легший запит — сервер тільки токенізує текст, не запускає генерацію. Дешевше і швидше.

Корисно коли:
- Хочеш перевірити чи вмістишся в context window перед відправкою
- Будуєш систему де треба контролювати довжину контексту

---

## Context window = input + output разом

Частa помилка: думати що 200k — це лише для input.

```
context window = input_tokens + max_tokens (output)
```

Якщо ти відправив промпт на 190k токенів і поставив `max_tokens: 20000` — отримаєш помилку, бо 190k + 20k = 210k > 200k. Треба або зменшити промпт, або `max_tokens`.

---

## Токени зростають з кожним turn'ом

В multi-turn діалозі кожен наступний запит включає всю попередню историю:

```
Turn 1: 50 input tokens
Turn 2: 50 + assistant_response + 30 = ~150 input tokens
Turn 3: 150 + assistant_response + 25 = ~300 input tokens
...
```

Довга розмова може коштувати значно більше ніж здається на початку.

---

## Підводні камені

**1. Один токен ≠ одна літера.**
Якщо обрізаєш текст по символах щоб "вмістити в ліміт" — це не працює. Треба токенізувати.

**2. Форматування збільшує кількість токенів.**
JSON, XML, Markdown — додають токени для лапок, дужок, відступів. Мінімальний plain text — дешевше.
