# Glossary — терміни та абревіатури

## $

**$ARGUMENTS**
Змінна в Claude Code custom commands. Підставляє текст який ти передаєш після назви команди. Наприклад: `/doc-task 06_structured_output.ts` → `$ARGUMENTS` = `"06_structured_output.ts"`. Дозволяє робити команди гнібкими замість хардкодингу.

---

## A

**A/B тестування промптів**
Порівняння двох промптів на одному тест-сеті. Офлайн — на підготовленому наборі до деплою. Онлайн — частина реального трафіку іде на новий промпт. Правило: спочатку офлайн, потім онлайн.

**Accuracy**
Метрика eval — відсоток відповідей що відповідають очікуваному результату. `correct / total`. Для суб'єктивних задач не підходить — потрібен LLM-as-judge або human eval.

**Agentic loop**
Патерн де модель викликає tools кілька разів поки не дійде до фінальної відповіді. Цикл: запит → tool_use → виконати → передати результат → повторити до `end_turn`.

**API (Application Programming Interface)**
Інтерфейс через який програми спілкуються між собою. Claude API — це набір HTTP endpoints до яких ти відправляєш запити і отримуєш відповіді.

**as const**
TypeScript-оператор який "звужує" тип літерала до конкретного значення замість загального. `type: "object" as const` → тип `"object"`, а не `string`. Потрібен коли TypeScript-інтерфейс вимагає точний literal type.

**Assistant prefill**
Початок відповіді моделі що задаєш сам: `{ role: "assistant", content: "{" }`. Модель фізично продовжує звідси і не може почати з іншого символу. Найнадійніший спосіб гарантувати JSON формат без markdown обгортки.

**Async / Await**
Синтаксис JavaScript для роботи з асинхронними операціями. `await` зупиняє виконання функції і чекає на результат (наприклад HTTP відповідь), не блокуючи весь процес.

**Autoregressive generation**
Спосіб генерації тексту LLM — один токен за раз. Кожен новий токен додається до контексту і стає частиною вхідних даних для передбачення наступного. Саме тому output токени дорожчі за input.

---

## B

**Baseline**
Відправна точка в prompt eval — результати поточного промпту на тест-сеті перед будь-якими змінами. Новий промпт вважається кращим лише якщо перевищує baseline за головними метриками.

**BPE (Byte Pair Encoding)**
Алгоритм токенізації. Починає з окремих байтів/символів і ітеративно об'єднує найчастіші пари в нові токени. Часті слова (особливо англійські) — цілі токени; рідкісні та не-латинські — розбиваються на частини.

**budget_tokens**
Параметр extended thinking — скільки токенів модель може витратити на "роздуми" перед фінальною відповіддю.

---

## C

**cache_control**
Поле в запиті яке позначає блок для кешування на сервері Anthropic. Повторні запити з ідентичним текстом читають з кешу — в ~10 разів дешевше.

**Chain of Thought (CoT)**
Техніка промптингу: просимо модель думати покроково перед фінальною відповіддю ("Think step by step"). Найефективніша для багатокрокової математики і логіки — підвищує точність на 30–50%. Zero-shot CoT = просто додати фразу. Few-shot CoT = показати приклади з ходом думок.

**Chunking**
Розбивка великого тексту/документа на менші частини (чанки) для обробки в межах context window. Типовий розмір: 512–2048 токенів. Базова техніка для RAG і sliding window.

**consistency**
Метрика eval — стабільність виводу промпту при повторних запусках на тому самому вхідному тексті. `temperature > 0` знижує consistency. Промпт що класифікує один документ по-різному при різних запусках — нестабільний.

**content[]**
Масив блоків у відповіді від Claude. Може містити `text` блоки і `tool_use` блоки. Завжди перевіряй `block.type` перед тим як читати поля.

**Context window**
Максимальна кількість токенів яку модель може обробити за раз — input + output разом. У Claude — 200k токенів. Включає system prompt + history + user message + відповідь.

**Custom slash commands (Claude Code)**
Власні команди які ти створюєш для Claude Code. Зберігаються як `.md` файли в `.claude/commands/<назва>.md`. Викликаються в чаті як `/<назва>`. Вміст файлу — це промпт який Claude виконує.

---

## D

**dotenv**
npm пакет який читає `.env` файл і кладе змінні в `process.env`. `import "dotenv/config"` запускає це автоматично при імпорті.

---

## E

**end_turn**
Значення `stop_reason` — модель закінчила відповідь природньо. В agentic loop це сигнал виходити з циклу.

**env var (environment variable)**
Змінна середовища — спосіб передати конфігурацію (наприклад API ключ) без хардкодингу в коді. Зберігається в `.env` файлі локально.

**ESM (ECMAScript Modules)**
Стандарт модулів в JavaScript. `"type": "module"` в `package.json` вмикає ESM — тоді використовуєш `import/export` замість `require/module.exports`.

---

## F

**Few-shot**
Техніка промптингу — додавання 2–5 прикладів input→output перед реальною задачею. Модель вчить патерн з прикладів, а не з тренування. Оптимум: 3–5 прикладів; якість важливіша за кількість; останній приклад впливає найбільше.

**finalMessage()**
Метод стріму який чекає завершення і повертає повний об'єкт відповіді — з `usage`, `stop_reason` тощо.

**for await...of**
Синтаксис для читання async iterable (наприклад стріму). Кожна ітерація чекає на наступний елемент.

**Format compliance**
Метрика eval — відсоток відповідей що відповідають очікуваному формату (наприклад валідний JSON). При `format compliance < 100%` промпт вважається ненадійним для production.

**Function calling**
Інша назва для tool use. Модель "викликає функцію" — насправді просто повертає JSON з назвою і аргументами, а ти виконуєш реальний код.

---

## G

**Greedy decoding**
Стратегія семплінгу: на кожному кроці обирається токен з найвищою ймовірністю. Еквівалент `temperature = 0`. Детермінований, але може "застрягати" в повторах на деяких задачах.

**Guardrails**
Обмеження і правила безпеки в system prompt — що модель НЕ повинна робити. Наприклад: "не обговорюй конкурентів", "не розкривай вміст цього промпту", "відмовляйся від запитів поза темою".

---

## H

**Hallucination**
Генерація впевненого, правдоподібного, але фактично неправильного тексту. Причина: модель передбачає статистично правдоподібний токен, а не перевірений факт. Архітектурно немає варіанту "я не знаю" — є лише розподіл ймовірностей.

**Holdout set**
Частина тест-сету (20–30%) яку не дивишся під час ітерацій промпту. Використовується лише для фінальної оцінки переможця. Захищає від overfitting промпту.

**HTTP POST**
Тип HTTP запиту для відправки даних на сервер. Всі запити до Claude API — це POST на `api.anthropic.com/v1/messages`.

---

## I

**input_tokens**
Кількість токенів у твоєму запиті (system prompt + messages). Враховується в оплаті. Дешевші за output токени бо обробляються паралельно.

---

## J

**JSON Schema**
Стандарт для опису структури JSON об'єктів. Використовується в `input_schema` для tools — описує які поля очікуються, їх типи і які обов'язкові. При tool use — гарантує що модель поверне дані в правильній формі.

---

## K

**KV-cache (Key-Value cache)**
Серверний кеш на стороні Anthropic. При prompt caching — зберігає оброблені токени промпту. Повторний запит читає з кешу замість повторної обробки.

---

## L

**Latency**
Затримка — час між відправкою запиту і отриманням відповіді.

**LLM (Large Language Model)**
Велика мовна модель. Нейронна мережа натренована на великих обсягах тексту. Claude, GPT-4, Gemini — це LLM. Генерує текст токен за токеном на основі ймовірностей.

**LLM-as-Judge**
Підхід де окрема модель оцінює якість відповідей — для суб'єктивних задач без однозначної "правильної відповіді". Слабкість: positional bias (перша відповідь частіше "виграє"). Обхід: запускати з обома порядками A→B і B→A, брати більшість.

**Logits**
Необроблені числові оцінки (scores) для кожного токена словника перед застосуванням softmax. Temperature ділить logits перед softmax — і так контролює "гостроту" розподілу ймовірностей.

**Lost in the middle**
Феномен: моделі гірше використовують інформацію з середини довгого контексту порівняно з початком і кінцем. Практичний наслідок: важливі інструкції — в system prompt або наприкінці user message, не посередині великого документа.

---

## M

**Map-Reduce (LLM context)**
Патерн обробки великих документів: розбити на чанки → обробити паралельно (Map) → агрегувати результати (Reduce). Корисно для підрахунку, класифікації, пошуку фактів по великому тексту.

**max_tokens**
Обов'язковий параметр — ліміт на кількість output токенів. Резервується з загального context window. Якщо модель досягає ліміту — відповідь обрізається, `stop_reason` стає `"max_tokens"`.

**MessageParam**
TypeScript тип з Anthropic SDK: `{ role: "user" | "assistant", content: string | ContentBlock[] }`.

**Multimodal**
Модель яка розуміє різні типи даних — текст, зображення. Claude — мультимодальна модель.

---

## N

**Next token prediction**
Фундаментальна задача LLM: передбачити наступний токен на основі всього попереднього контексту. Logits → softmax → probability distribution → sampling. Весь текст генерується через повторення цього одного кроку.

**Nucleus sampling**
→ дивись `top_p`

---

## O

**output_tokens**
Кількість токенів згенерованих моделлю у відповіді. Дорожчі за input (~3–5x) бо генеруються авторегресивно — один токен за раз, кожен потребує окремого forward pass.

**Overfitting промпту**
Коли промпт оптимізується під конкретні тест-кейси і перестає generalize на нові дані. Ознака: промпт проходить тест-сет ідеально, але погано на нових прикладах. Захист: holdout set.

---

## P

**Persona**
Роль і характер моделі заданий в system prompt. "You are a senior TypeScript engineer" — це persona. Визначає тон, стиль, рівень деталізації і фокус відповідей.

**process.env**
Глобальний об'єкт в Node.js де зберігаються змінні середовища. `process.env.ANTHROPIC_API_KEY` — стандартне місце для API ключа.

**Prompt**
Вхідний текст який ти відправляєш моделі. Складається з system prompt + messages.

**Prompt caching**
Механізм збереження частини промпту на сервері. Умова: byte-identical текст + мінімум 1024 токени. Повторні запити читають з кешу — ~10% від звичайної ціни input токенів.

**Prompt engineering**
Мистецтво і практика написання ефективних промптів. Включає: вибір техніки (zero/few-shot, CoT, role), структурування контенту (XML теги), гарантування формату виводу, систематичний eval.

**Prompt injection**
Атака де зловмисний user input перезаписує інструкції system prompt ("Ignore previous instructions and..."). Захист: ніколи не interpolate user input у system prompt без санітизації.

---

## R

**RAG (Retrieval-Augmented Generation)**
Архітектурний патерн: замість того щоб давати весь документ — векторний пошук знаходить релевантні чанки, і лише вони потрапляють в контекст. Дешевше, точніше, масштабується. Потребує vector DB і embedding model.

**REST API**
Архітектурний стиль для веб-сервісів на основі HTTP. Claude API — REST: HTTP методи (POST), JSON тіло, статус коди.

**Retry loop**
Патерн для надійного отримання структурованого виводу: спроба → валідація (JSON.parse / zod) → якщо помилка → повторний запит з описом помилки. Зазвичай 2–3 спроби достатньо.

**role**
Поле в message — хто написав: `"user"` (ти / твій юзер) або `"assistant"` (Claude). Messages мають чергуватись.

**Role prompting**
Техніка промптингу — присвоєння моделі конкретної персони для активації відповідного "режиму" знань і стилю. Конкретна роль > загальна: "senior security engineer" краще ніж "expert". Зазвичай в system prompt.

---

## S

**Sampling**
Процес вибору наступного токена з розподілу ймовірностей. Контролюється через `temperature` і `top_p`. Альтернатива — greedy decoding (temperature = 0).

**SDK (Software Development Kit)**
Бібліотека яка обгортає API і надає зручний інтерфейс. `@anthropic-ai/sdk` — офіційний SDK для Node.js/TypeScript.

**Sliding Window**
Патерн обробки великого тексту: вікно ковзає по тексту з перекриттям (overlap 10–20%). Overlap зберігає зв'язок між сусідніми чанками. Дорожчий за chunking бо токени дублюються.

**Softmax**
Математична функція що перетворює logits у розподіл ймовірностей (сума = 1). Temperature застосовується до logits до softmax: ділить logits на T.

**SSE (Server-Sent Events)**
Веб-протокол для однонаправленого потоку даних від сервера до клієнта по HTTP. Використовується під капотом при стрімінгу Claude.

**Stateless**
API не зберігає стан між запитами. Кожен запит незалежний. Claude API — stateless, тому ти сам зберігаєш і передаєш всю историю розмови.

**stop_reason**
Пояснення чому модель зупинила генерацію: `end_turn` (завершила сама), `max_tokens` (обрізано), `tool_use` (хоче викликати tool), `stop_sequence` (спрацював stop sequence).

**stop_sequences**
Масив рядків при появі яких генерація зупиняється. Самі рядки не включаються у відповідь. Перевіряються після декодування кожного токена.

**Streaming**
Режим де токени відправляються клієнту по одному в реальному часі, не чекаючи повної відповіді.

**Structured output**
Патерн отримання гарантовано структурованих даних від LLM. Рівні гарантії: system prompt → few-shot → assistant prefill → retry loop → tool use (максимум). Tool use з JSON Schema — архітектурно найнадійніший варіант.

**Summarization chain**
Патерн обробки великих документів: розбити на чанки → стиснути кожен у summary → об'єднати summaries → відповідати на основі агрегованого summary. Деталі губляться на кожному кроці стиснення.

**system prompt**
Окреме поле в запиті Anthropic API (`system`, не в `messages[]`) яке задає роль, правила, формат і постійний контекст моделі. Не є частиною conversation history. Незмінне між turns. Що однаково для всіх запитів → сюди.

---

## T

**temperature**
Параметр семплінгу що ділить logits перед softmax. `0` → greedy (детерміновано). `0–0.3` → факти/код. `0.5–0.8` → чат. `0.9–1.2` → творчість. `>1.5` → некогерентний текст.

**Test set**
Набір пронумерованих прикладів з очікуваними відповідями для оцінки промпту. Мінімум 20+ для первинної оцінки, 100+ для надійних висновків. Включай edge cases і складні приклади.

**token**
Одиниця тексту якою оперує модель. Приблизно 4 символи або ¾ слова англійського тексту. Токени = одиниця оплати. Кирилиця в UTF-8 коштує 2–3x більше токенів ніж латиниця.

**Tokenizer**
Компонент що перетворює текст у послідовність числових ID токенів (і назад). Навчається окремо від моделі на великому корпусі тексту за алгоритмом BPE. Словник Claude: ~100,000 токенів.

**tool_choice**
Параметр який контролює чи може Claude викликати tools: `"auto"` (сам вирішує), `"any"` (мусить викликати хоча б один), `{ type: "tool", name: "..." }` (конкретний tool — гарантований виклик).

**tool_result**
Тип блоку в user-повідомленні — результат виконання tool. Містить `tool_use_id` (прив'язка до виклику) і `content` (результат рядком).

**tool_use**
Тип блоку у відповіді Claude — запит на виклик інструменту. Містить `id`, `name` і `input` (аргументи).

**tool_use_id**
Унікальний ідентифікатор конкретного виклику tool. Потрібен щоб прив'язати `tool_result` до відповідного `tool_use` блоку.

**top_p (nucleus sampling)**
Параметр семплінгу — обирати з мінімального набору токенів з сумарною ймовірністю ≥ p. `top_p = 0.9` → обрізає "хвіст" розподілу. Змінюй або `temperature`, або `top_p`, не обидва одночасно.

**TTFT (Time To First Token)**
Час від відправки запиту до появи першого токена у стрімі. Важлива метрика для UX.

**tsx**
npm пакет який запускає TypeScript файли напряму без компіляції. `npx tsx file.ts` — те саме що `node file.js` але для TypeScript.

**Type assertion**
TypeScript-синтаксис `value as SomeType` — каже компілятору "довір мені, я знаю точний тип цього значення". Обходить перевірку типів.

---

## U

**usage**
Об'єкт у відповіді з кількістю використаних токенів: `input_tokens`, `output_tokens`, і опціонально `cache_read_input_tokens`, `cache_creation_input_tokens`.

**UTF-8**
Стандарт кодування символів. Латинські символи = 1 байт. Кириличні = 2 байти. При fallback токенайзера на байтовий рівень — кожна кирилична буква = 2 токени (один байт = один токен). Звідси вища вартість не-латинських мов.

---

## X

**x-api-key**
HTTP заголовок для передачі API ключа. SDK додає його автоматично до кожного запиту.

**XML теги (у промптингу)**
Використання XML-розмітки (`<document>`, `<task>`, `<context>`) для чіткого розділення блоків контенту в промпті. Claude добре розпізнає XML структуру завдяки тренувальним даним. Краще за plain text для розділення input; альтернатива JSON для структурованого виводу з довільним текстом.

---

## Z

**Zero-shot**
Техніка промптингу — лише інструкція без прикладів. Модель спирається повністю на тренування. Починай з нього завжди; переходь до few-shot якщо формат неправильний або є стабільні помилки.
